# 资产提取手册（角色 · 场景 · 道具）

## 这一步做什么

扫当前集剧本，捞出角色、场景、道具三类资产，与项目存量比对去重后挂到当前集。
总方针：**提漏好于提滥**——只收本集真实出现、且值得独占一份图片资产复用的条目。

## 读取阶段（四个工具）

1. `read_script_for_extraction` — 本集剧本
2. `read_existing_characters` — 项目存量角色 + 本集已关联角色
3. `read_existing_scenes` — 项目存量场景 + 本集已关联场景
4. `read_existing_props` — 项目存量道具 + 本集已关联道具

## 三类资产的字段要求

### 角色 → `save_dedup_characters`

- **name**（必填）：角色全名
- **role**：主角/配角/龙套
- **appearance**：300-500 字样貌——性别、年龄感、五官、身材体态、气质。**性格不许单列**，必须蒸进外貌：写"冷峻"要落成"眼神发冷、表情收着、几乎不笑"
- **styling**：妆造——发型、服装、妆面、配饰
- **description**：背景与人物关系（选填）

### 场景 → `save_dedup_scenes`

- **location**（必填）：具体场所名
- **time**：时段（白天/黄昏/深夜……）；同一地点换时段即算新场景
- **prompt**：空间、陈设、年代质感、标志视觉元素——纯背景，人物禁入
- **lighting**：光源、色调、明暗、气氛

### 道具 → `save_dedup_props`

- **name**（必填）：道具名
- **type**：日常/武器/交通/装饰/文件……
- **description**：只写物件自身的物理外观（材质、颜色、形状、大小、新旧、磨损），不写剧情作用，不扯它与角色或他物的关系

道具**不产出图片提示词**——生图前由提示词 Agent 按白底单品规范专门生成。

## 道具准入（最严的一道门）

道具要做成白底单品图供视频特写引用，成本很高，所以只收剧情关键道具：单集一般 **0-3 件**，超了就按剧情权重砍到 3 件。

下面两条**必须同时成立**：
1. **剧情上有一票**：它的出现、交接、损毁或被发现能扳动情节（凶器、信物、关键文件、定情礼物、证据）
2. **画面上有一票**：后续分镜会给它特写或反复入画，外观需要固定下来

**三问自测**（任何一问答"否"就放弃）：
- ① 把它删掉剧情还成立吗？→ 成立就别提（它只是摆设）
- ② 是角色顺手就用的日常物吗（手机、筷子、水杯、香烟、雨伞）？→ 是就别提
- ③ 算场景陈设吗（桌椅、灯具、门窗、挂画、餐具）？→ 算就别提（归场景描述管）

**典型不合格样本**：随用随弃、不影响走向的普通物件；家具与场景陈设；一提就再没下文的东⻄；角色的日常穿戴（进角色妆造）。本集若真没有合格道具，**别硬凑**——`save_dedup_props` 传空数组。

## 保存阶段

5. 范围只限本集真实涉及的角色、场景、道具
6. `save_dedup_characters` — 存角色并自动挂本集
7. `save_dedup_scenes` — 存场景并自动挂本集
8. `save_dedup_props` — 存道具并自动挂本集

## 边界与去重纪律

- 服务对象是"当前集"，不是全项目重扫
- 项目里已有、本集还没挂的资产：复用并挂上，不要重造
- 匹配键：角色/道具看名称，场景看【地点+时间段】，均为精确匹配，命中即复用
- 近似名合并：名字带括号注记时只比括号前主体——「林小雨（主角）」＝「林小雨」；判定依据是 `read_existing_characters` / `read_existing_props` 返回的 `normalized_name`（场景对应 `normalized_location`）
